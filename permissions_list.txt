HOW THE PERMISSION SYSTEM WORKS
--------------------------------
1. Every permission is stored as a string in the PermissonModel (database table).
2. Permissions are grouped into GroupModel objects (e.g. "finance_accounts").
3. Users are linked to groups via AssignGroupPermission.
4. On every API request, HasCustomPermission checks:
     a. Is user a superuser? → Allow everything.
     b. Does the URL path match a pattern in protected_urls.py? → Check that specific permission.
     c. Does the view define action_permissions? → Check per HTTP method.
     d. Does the view define required_permission? → Check that one permission.
5. Frontend fetches /api/account/v1/authorization/get_user_all_permissions/ on load.
   → filterNavigationByPermissions() hides nav items the user has no access to.

PERMISSION NAMING CONVENTION
------------------------------
  module_management       → Master section permission (grants broad access to a module)
  module:action           → Granular sub-permission (e.g. member:create, restaurant:order_create)

To run bootstrap: python manage.py bootstrap_auth

════════════════════════════════════════════════════════════════════════════════
  SECTION 6 — QUICK SETUP COMMANDS
════════════════════════════════════════════════════════════════════════════════

  # Seed all permissions and groups (run this on fresh install or after changes):
  python manage.py bootstrap_auth

  # Create a superuser (bypasses all permission checks):
  python manage.py createsuperuser

  # Assign a user to a group via Django shell:
  from account.models import AssignGroupPermission, GroupModel
  from django.contrib.auth import get_user_model
  User = get_user_model()
  user = User.objects.get(username="staff_user")
  group = GroupModel.objects.get(name="finance_accounts")
  agp, _ = AssignGroupPermission.objects.get_or_create(user=user)
  agp.group.add(group)
